Develop a Python framework that continuously collects local system metrics, outputs structured JSON/JSONL and provides automated testing to validate functionality and data integrity.

Data Collection
Metrics to collect:
CPU: total usage, per-core usage.
Memory: total, used, free, available.
Disk: per partition total, used, free.
Network: bytes sent and received per interface.
Configurable collection interval (e.g., every 5 seconds).
Use Python libraries like psutil.
Runs under normal user permissions (no root/admin needed).
Data Storage
Write collected metrics into JSONL files.
Each record timestamped for time-series analysis.
Example JSONL record:
{"timestamp": 1731462200,"cpu": {"total": 35.5, "per_core": [20.0, 50.0, 30.0, 42.0]},"memory": {"total": 16384, "used": 8192, "free": 4096, "available": 8192},"disk": {"C:": {"total": 512000, "used": 256000, "free": 256000}},"network": {"eth0": {"bytes_sent": 1234567, "bytes_recv": 2345678}} }
Report Generation
Optionally generate JSONL summary reports from collected metrics.
Aggregate statistics per time window:
Average CPU usage
Memory usage trends
Disk and network utilization
Output summary in JSON format.
Automated Testing
Test Artifacts:
test_report_template.json to aggregate test results.
Use Python pytest.
Project Architecture
collector.py — main metric collection module.
storage.py — JSON/JSONL writing and file rotation.
reporter.py — optional report generation.
config.json — collection interval, output paths.
tests/ — unit and integration test scripts.
run_metrics.sh — script to start collection.
run_tests.sh — run automated tests and generate test report.
Output Artifacts (Mandatory)
For reproducibility and testing, the project must generate:
requirements.txt — Python dependencies.
Dockerfile — containerized environment.
setup.sh — local environment setup.
run_test.sh — demo script for end-to-end test, including automated tests.
README.md — usage guide and API documentation.
test_report_template.json — template for collecting test results.

Implementation

Built the configurable sampling loop plus CLI so CPU/memory/disk/network stats stream into JSONL with optional duration/output overrides, all driven by config.json (lines 1-6) and exposed via run_metrics.sh (lines 1-16) (collector.py (lines 18-123)).
Added a thread-safe JSONL writer with timestamp-based rotation, along with helpers to read back recent records for reporting (storage.py (lines 15-64)).
Implemented a reporting engine that loads JSONL data, filters by the requested window, and emits averaged CPU, memory trend, disk, and network utilization summaries or files (reporter.py (lines 31-167)).
Created comprehensive automation assets: reproducibility requirements and Docker image (requirements.txt (lines 1-3), Dockerfile (lines 1-10)), end-to-end demo plus setup/test runners (run_test.sh (lines 1-30), run_tests.sh (lines 1-42)), and a JSON test-report template wired into the pipeline (test_report_template.json (lines 1-9)).
Documented the workflow and APIs in the README (README.md (lines 1-82)) and added pytest coverage that exercises the collector mocks, storage rotation, and reporting aggregates (tests/test_collector.py (lines 28-71), tests/test_storage.py (lines 6-20), tests/test_reporter.py (lines 7-35)).
